# 来源上下文、陪伴预设与简单客户端验收（API 0.5）

验收日期：2026-11-19（Asia/Shanghai）。本轮承接用户指定的 billion-context、两套 Soulweave 参考，以及“功能预设好、客户端尽可能简单”的要求。在[API 0.4 内测版本](usability-acceptance.md)上独立实现来源记忆、实际规划预览和简单默认流程；正式客户端视觉仍交给 Gemini。结论仅为 **SSH 保护环境中的功能内测通过**，不是公开生产、可靠语义记忆或真实陪伴质量证明。

## 部署与恢复结论

- 已部署 **API 0.5.0 / 74 个 OpenAPI 路径 / schema5**。只使用原有 `allira-dev`、低权限 `allira`、单 Uvicorn worker、`127.0.0.1:8000`，不 reload、不信代理头；业务服务未启用开机自启。没有新增公网监听、域名、防火墙或 SSH 登录变更。
- SSH 隧道保留；可打开 `http://127.0.0.1:8000/test/`，独立后台 `/admin/` 仍须服务器一次性链接，接口文档 `/docs`。普通账号、开发身份与管理认证不互相赋权。
- 先确认 running/reserved 为零，再停止原服务、创建一致性快照、保存旧前端与完整原受保护环境。维护配置仅覆盖已知非秘密键：Mock、0.3 秒演示分片、极速模型空、最近窗口临时为 1，原 Key 保留原位不回显。该窗口只是两轮即可触发来源块的测试条件，不是新的产品默认。
- 核验冻结 UI 清单后正常构建部署，只运行约定的唯一实际 Mock 专项。通过并声明业务 LIVE 冻结后，逐字节恢复完整原环境并检查 SHA-256 一致，再只重启同一个服务。恢复后 **info=openai、readyz=ready、0.5.0、74 路径、schema5、running/reserved 均为零**；临时窗口覆盖随原文件恢复撤销。
- 原经济测试模型仍为此前授权的 `deepseek-flash`、输出上限 256 Token；真实极速未配置，按原策略回退。不通过再次生成验证恢复，**本轮没有自动真实模型请求**。此前有限真实链路结果保留在[MVP 历史验收](mvp-acceptance.md)，不拼入本轮成绩。
- 每日同机 `allira-backup.timer` 继续 enabled/active，保留最近 7 份合法快照；业务 API disabled at boot 与备份定时器分别管理。没有覆盖运行库或宣称异机灾备。

| 场景 | 已实现行为及边界 |
| --- | --- |

| 可选风格 | 主动展开后可选“温柔倾听”“一起行动”。风格不代表系统确认恋爱、独占或亲密关系，不根据目标用户性别替她们决定称呼和边界。 |
| 创建与费用 | 服务端 owner+clientSetupId 原子幂等建立空会话与中性关系说明；不调用模型、不建 Run/消息/角色/钱包、不扣能量。openingHint 明确是页面建议，不冒充 AI 回复。未知响应只主动重试原 UUID+风格，不自动重发或换 ID；已删除目标不复活。 |
| 高级能力 | 账号、角色/记忆、历史迁移、检索/归档/分叉、能量、上下文检查和技术参数仍可用，收进默认折叠的设置与高级工具，不为简化而移除旧功能。关闭设置、切换会话/账号会清理敏感来源与预览。 |

## 来源记忆与实际上下文

| 能力 | 实现与约束 |
| --- | --- |
| 人工确认卡 | fact / preference / boundary / relationship 是用户提供的分类文本，不是系统验证事实；支持创建、修改、启停、删除。来源仅允许本会话真实相邻 completed user→assistant 对的 user。每会话最多 50 张、全部卡内容合计 20000 字符、单卡 2000；启用卡和核心设定/当前输入必须保留，超预算直接 413，不静默丢掉边界。 |
| 来源摘录块 | 每个离开最近窗口的真实完成对保存两条原消息 ID、序号与确定 ID；每侧最多摘录 500 字符并明确截断。只限制有界视图，不因预算删除块或原文；处理水位单调前进、同一对不重复归档。旧 summary 保存为无精确来源的 legacy_summary，显式警告、不伪造出处。 |
| 检索与原文 | 分页和绑定 owner/conversation/q 的签名游标；q 仅子串检索摘录。用户显式点选才读取原文，重新核验准确完成对。停用只使后续历史提示不采用该块，不等于删除原聊天、卡片、下载或备份。 |
| 实际预览 | 预览和 Run 复用同一规划器及安全检查；SAVEPOINT 中规划后始终回滚业务变化，返回完整消息、分段字符数、入选/待写块与遗漏计数。不创建 Run/事件/能量预留、不调用模型；正常认证的 lastSeenAt 维护不在绝对无写入承诺内。它是快照，不检查余额/频率/容量，不锁定之后的设定或历史。 |
| 归档与删除 | 会话 JSON/Markdown 和账号归档包含启用及停用卡/块，仍受会话 50000 合并记录/16MiB、账号 100000 记录/32MiB 等限制，超限拒绝不截断。分叉不复制任何卡片、块或旧摘要；当前角色/核心/关系设定快照政策保留，不能说成完全还原过去。删除会话/账号级联在线卡块，历史备份保留风险明确。 |

默认最近 8 对、历史视图 6000 字符、总 Prompt 120000 字符；计量为 characters_not_tokens。没有使用 LLM 自动总结、向量检索、情绪模型或多级压缩内核；不承诺永不遗忘、百万 Token、固定压缩收益或可靠语义理解。完整消息预览属于敏感响应，折叠不等于未进入内存，不放入公共缓存。

## 审计归属修复与留存边界

本轮只读复核发现“没有 Run/usage 的空预设聊天先被管理读取/删除，之后删号无法再归属其审计”的问题。新增内部 admin_audit.ownerId、可恢复资源/usage 的增量回填及删号同事务清理，公开 DTO 不新增 owner 字段。后续同 ID 不同类型/不同用户的碰撞回归要求：明确他人 owner 不能被回退误删；回退只适用 NULL owner，并按 user/conversation/run/character 类型限定。参数化用例验证另一身份与会话仍有效、FK/事务正常；独立只读复核已确认修复。

升级前已经删除、没有 usage 或可恢复资源链接的旧审计不能凭空归属，可能保留无正文的 UUID/动作/时间；未知类型不猜测。账号删除只清在线数据，下载/历史备份不追溯物理擦除。每日同机快照、校验及全新离线目标恢复继续保留[上一阶段证据](usability-acceptance.md)，不扩称本轮做过异机灾备或任意历史迁移。
